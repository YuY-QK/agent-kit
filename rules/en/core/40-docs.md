
## Documents

- Documents in a repository are Markdown by default and live in `docs/` or a fitting subfolder; produce Word, PDF, spreadsheets or slides only when I ask.
- Write each rule or decision in the authoritative document that owns it (requirements in the PRD, technical choices in the technical design or an ADR) and link to it elsewhere instead of copying summaries.
- When requirements, architecture, data contracts, permissions or delivery scope change, update the authoritative document first, then the code.
- A README describes only what really runs and the structure that really exists.
