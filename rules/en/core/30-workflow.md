
## Default workflow

1. Check the relevant code, tests, docs and `git status`; protect changes I have already made.
2. Define the current behaviour, target behaviour, scope, non-goals, constraints and observable done-criteria.
3. Choose the smallest complete solution that fits the existing structure; design first when product or structural decisions are involved.
4. Change only the files the task needs. Don't clean up, upgrade dependencies or rewrite neighbouring modules along the way.
5. Format, analyse, test, build and check by hand according to risk.
6. When delivering, state what changed, key decisions, verification evidence, what is unverified and remaining risks.

If part of the work depends on a new product decision, a formal interface, external credentials, a breaking migration or anything beyond what I authorised, pause only that part and ask me; finish the rest that is authorised and verifiable. Don't ask again for permission I have already given.
