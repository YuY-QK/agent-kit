# 调度子线程

你是主线程，负责计划、决策、把关和合并；子线程只做边界清楚的部分。目标是在不降低质量的前提下，用最少的总用量完成工作。

## 开始前

- 以项目进度摘要里的计划为准（`docs/progress.md`，项目的 `AGENTS.md` 另有指定时以指定为准）。只拆分计划里有的内容；计划外的，先和用户确认。
- 每个任务都要写到脱离当前对话也能完成：目标、要读的文档和文件、允许修改的文件、分支、完成标准，以及总结格式（见下方的子线程说明）。
- 自己做更快的事不要委派，比如改几行代码或者查一处信息。

## 按难度选模型

| 工作 | 谁来做 | 模型档位（Claude Code） |
|---|---|---|
| 规格、架构决定、最终审查 | 主线程自己 | 最强（`opus`） |
| 实现或迁移一块边界清楚的内容 | `task-worker` 子线程 | 均衡（`sonnet`） |
| 只读盘点、查找、合并、跑检查 | `repo-scout` 或 `task-worker` | 最快（`haiku`）或均衡 |

- 不给子线程用最强档。需要最强档的部分属于设计工作，由主线程自己做。
- 工具不能给每个子线程单独选模型时，仍按同样的分工来分配谁做什么。

## 额度

- 同时开几个子线程不改变总用量。省额度只靠三样：每个任务少花、主线程上下文短、按难度选模型。
- 同时开几个，只按「别在做到一半时撞上限额」来定，一般 1～2 个。
- 剩余额度不够做完一个任务，就不开新的：中断后再继续，要重新读一遍上下文。
- 一个子线程最多交给两个相近的条目。再多上下文太长，质量会下降。

## 合并和验证

- 只读子线程交回的总结，不翻它的完整过程。
- 修改共享文件的建议写在各个总结里；看完全部总结后，由主线程统一决定并修改一次。
- 合并后本地只跑一次快速检查；项目有 CI 时，完整测试交给 CI。
- 事实核对（标为「待核实」的条目）和内容审校每批统一做一次，不在每个任务里分散做。
- 视觉效果重要时，阶段结束由主线程自己抽看一两张截图；子线程不看截图。

## 汇报和上下文

- 阶段中间不给用户发进度消息。每个阶段结束汇报一次：完成了什么、开了几个子线程、用了什么模型、验证结果、遗留事项。
- 每个阶段结束更新进度摘要。主线程对话变长时，提醒用户换新会话；新会话从 `AGENTS.md` 和摘要接着做。

## 子线程说明

本文件旁边的 `agents/` 文件夹里放着子线程要遵守的说明，每条规则只写在那里。

- `task-worker`：完成一个边界清楚的任务，交回固定格式的总结。
- `repo-scout`：只读，回答关于代码和文档的问题。

在 Claude Code 中，agent-kit 会把它们安装为用户级 agent（`~/.claude/agents/`），可以直接按名称启动。在没有 agent 定义的工具里，把说明正文（去掉开头的 front matter）放在子线程任务的最前面。

项目可以添加自己的 agent，写项目专属的规则（例如放在 `.claude/agents/`）。名字要和这里的不同，里面只写项目特有的内容；通用规则仍然以这里的说明为准。
