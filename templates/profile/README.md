# agent-kit profile

[简体中文](README.zh-CN.md)

This repository holds my personal settings for [agent-kit](https://github.com/YuY-QK/agent-kit): the languages the assistant uses, how I like to work, my own rules and skills, and the results of conflict merges. agent-kit combines them with its shared rules and skills and installs the result for Claude Code and Codex.

Keep this repository **private**. It contains no passwords or machine paths, but it does describe how you work.

## How it fits together

| Where | What | Synced |
|---|---|---|
| agent-kit repository (anywhere on disk) | Shared rules, skills, subagents, scripts | Public repository, `git pull` |
| `~/.config/agent-kit/profile/` (this repository) | Your settings, rules, skills, overrides | This private repository |
| `~/.config/agent-kit/machine.sh` | This computer only: where your projects are | Not synced |
| `~/.claude/`, `~/.codex/`, `~/.agents/skills/` | What gets installed | Generated by `scripts/install.sh` |

Every time you run `scripts/install.sh`, agent-kit reads this profile, builds the global rules and the skill list, and installs them. Nothing in this repository is read directly by Claude Code or Codex, so after changing anything here, run `scripts/install.sh` again.

## Files

| Path | Contents |
|---|---|
| `profile.sh` | Your preferences: languages, about you, workflow, skills, tools. See below |
| `rules/*.md` | Your own rules, added to the end of the global rules in file-name order |
| `skills/<name>/SKILL.md` | Your own skills, installed next to the shared ones |
| `agents/<name>.md` | Your own subagents for Claude Code (`~/.claude/agents/`) |
| `overrides/` | Your versions of shared files, saved by the conflict page; they replace the generated ones |
| `README.md`, `README.zh-CN.md` | This description |

Folders that don't exist yet can simply be created.

## Settings in profile.sh

`profile.sh` holds only `KEY="value"` lines; agent-kit reads them without running the file.

| Key | Values | Meaning |
|---|---|---|
| `PROFILE_VERSION` | `1` | Format version. Don't change it |
| `UI_LANG` | `en`, `zh-CN` | Language of agent-kit's own terminal messages and web pages |
| `CONTENT_LANG` | `en`, `zh-CN` | Language of the rule and skill texts that get installed |
| `REPLY_LANG` | a code (`en`, `zh-CN`, `ja`, …) or a language name | Language the assistant replies in |
| `DOCS_LANG` | `reply`, or a code or name | Language for documents, code comments and commit messages; `reply` means the same as `REPLY_LANG` |
| `WORK_MODE` | `solo`, `team` | Whether you work alone or in a team; changes the collaboration rules |
| `DESIGN` | `none`, `some` | Your design experience; with `none` the assistant proposes 2–3 design directions with its reasoning and lets you choose |
| `PLANNING` | `full`, `light`, `off` | How much planning before building: full documents, a short plan, or none |
| `COMMITS` | `conventional`, `free` | Commit message style (`feat: …`, `fix: …`, or free text) |
| `SCAFFOLD` | free text, or empty | Your own project scaffold, if new projects should start from it |
| `STACKS` | stack names separated by spaces (`flutter web`) | Which stack-specific skills to install |
| `SKILLS` | `all`, or skill names separated by spaces | Which shared skills to install |
| `TOOLS` | `claude`, `codex`, or both | Which tools to install for |

`CONTENT_LANG` and `REPLY_LANG` are independent: for example, English rule texts with replies in Chinese.

## Changing settings

The easiest way is agent-kit's settings page or the terminal questions; they check the values for you:

```bash
cd <agent-kit folder>
scripts/configure.sh --web     # settings page in the browser
scripts/configure.sh           # or questions in the terminal
scripts/install.sh             # install with the new settings
scripts/sync-profile.sh push   # save them to this repository
```

`scripts/install.sh --configure` asks the questions and installs in one go. You can also edit `profile.sh` directly, then run `scripts/install.sh`.

## Your own rules

Put rules that apply to all your projects in `rules/`, one topic per Markdown file. They are added after the shared rules, sorted by file name, so a number prefix sets the order:

```
rules/
  10-naming.md
  20-reviews.md
```

Example `rules/10-naming.md`:

```markdown
## Naming

- Name files in kebab-case.
- Write user-facing text in Simplified Chinese.
```

Start each file with a `##` heading so it fits into the global rules. Rules for a single project don't belong here; put them in that project's `AGENTS.md` or `docs/AI_RULES.md`.

To see the final result: `scripts/build.sh --rules`.

## Your own skills and subagents

- **Skill**: create `skills/<name>/SKILL.md` with front matter (`name`, `description`) and the instructions; other files in that folder (scripts, templates) are installed with it. A skill with the same name as a shared one replaces it.
- **Subagent** (Claude Code): create `agents/<name>.md` in Claude Code's agent format. One with the same name as a shared subagent replaces it.

Then run `scripts/install.sh`. To change a shared skill only slightly, an override (below) is usually better than a full copy.

## Overrides from the conflict page

When an installed file was changed by hand and agent-kit's version also changed, `scripts/install.sh` opens a merge page. What you save there goes into `overrides/`:

| Path | Replaces |
|---|---|
| `overrides/AGENTS.md` | The generated global rules |
| `overrides/skills/<name>/SKILL.md` | A shared skill |
| `overrides/agents/<name>.md` | A shared subagent |

Each override has a `.base` file next to it recording which agent-kit version it was based on. When agent-kit changes that file again, the installer marks the override as outdated and asks you to merge again, so your edits are never silently lost.

To drop an override and go back to agent-kit's version, delete the file and its `.base`, then run `scripts/install.sh`. You can also edit an override by hand.

## Syncing between computers

On this computer, after any change:

```bash
scripts/sync-profile.sh push "what changed"
```

On another computer, the first time:

```bash
git clone git@github.com:YuY-QK/agent-kit.git
cd agent-kit
scripts/sync-profile.sh clone git@github.com:<you>/agent-profile.git
scripts/install.sh
```

Afterwards, to get changes made elsewhere:

```bash
scripts/sync-profile.sh pull
scripts/install.sh
```

`scripts/sync-profile.sh status` shows where the profile is and whether it has unsaved changes. `scripts/install.sh` also reminds you when the profile has changes that aren't pushed yet. The project folders asked during setup are stored in `machine.sh`, not here, so each computer can keep its own.

## Cloud sessions

Claude Code on the web starts each session in a fresh container. Projects set up with agent-kit's `start-project` skill or `scripts/enable-cloud.sh` install agent-kit there automatically. They can get these settings in two ways:

- **Profile repository** (`--profile repo`): the project only stores this repository's URL. The cloud session has to be able to read this private repository; if it can't, it says so and uses the defaults. You can also set `AGENT_KIT_PROFILE_REPO` in the cloud environment's variables.
- **Copy in the project** (`--profile copy` / `--with-profile`): `profile.sh` and `rules/*.md` are copied into the project's `.claude/agent-kit/` and committed. This always works, but anyone who can read the project can read them, so use it for private projects only. After changing your settings, run `scripts/enable-cloud.sh <project> --with-profile` again and commit.

## What not to put here

- Passwords, tokens, API keys or anything secret.
- Paths that only exist on one computer (they go in `machine.sh`, which is not synced).
- Project-specific rules (they go in the project).
- Copies of shared skills you haven't changed (they would stop receiving agent-kit's updates).

## Troubleshooting

| Problem | What to do |
|---|---|
| A change here has no effect | Run `scripts/install.sh`, then start a new session; rules are read when a session starts |
| The other computer still has the old settings | `scripts/sync-profile.sh pull`, then `scripts/install.sh` |
| `push` is rejected | Another computer pushed first: `scripts/sync-profile.sh pull`, then push again. If `pull` refuses because both sides changed, run `git -C ~/.config/agent-kit/profile pull --rebase`, then push |
| `profile.sh` has an invalid value | Run `scripts/configure.sh`; it shows the allowed values |
| A cloud session uses English defaults | The session couldn't read this repository; give it access, or use the copy in the project |
| You want to start over | Delete `profile.sh`; `scripts/install.sh` asks the questions again |
